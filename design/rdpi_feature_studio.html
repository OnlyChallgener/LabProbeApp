一、路由工具页信息架构(与官方 APP 全量对齐的主线)

「路由」一级页 = 工具面板

  • 网络测速卡(面板首卡,路由器原生测速)
  • 儿童上网(官方 APP 全功能对齐:上网计划 / 应用管控 / 停网时段 / 暂停联网)
  • 路由设置与诊断:映射与 UPnP · 防火墙 · 网络自检 · NAT 诊断 · IPv6 · DDNS · WireGuard · Webhook
  • 特征工作室(本期新增项,排在设置区之后;只是其中一项,不占满页面)

儿童上网 = 官方 APP 逻辑全量匹配

  • 页面:设备总览(绑定终端)→ 单设备页(上网计划卡片列表、应用黑/白名单、立即暂停/恢复、断网时段)
  • 操作逻辑:计划 = 时间窗 + 模式(internet_window / app_allowlist / app_blocklist);App→Hub 命令队列→路由器,与 Hub 既有 10 个 action 一一对应
  • 执行层:固件 child_guard(uci + sniffer),已真机闭环验证通过
  • 本期只补「路由工具页入口」,页面本身保持已对齐的实现不动

二、已验证的可行性基础(特征工作室)

特征库本体

原生识别引擎 nDPI,特征库纯 JSON:/usr/share/ndpi/db.default.json(hosts / payloads(hex+pos)/ user-agents / http-gets)。改完 ubus send rdpi_reinit 热加载,rdpi -e 名称 回读验证。

已有先例

/root/rdpi-backup/db.default.before-wechat.json — 本机已成功手工注入过微信规则。自定义叠加、修复误识别均可行。

防丢机制

官方 rdpi_feature_lib_upgrade.sh 升级会覆盖库 → Hub 持有「期望特征集」,检测库版本/SHA 变化后自动 diff 重放。

三、全链路:抓包 → 分析 → 特征包 → 同步

1抓包(NAS / 手机)tcpdump 目标设备流量;App 上传 pcap:POST /api/rdpi/captures
2分析(Hub)提取 DNS/SNI/UA/固定 hex/端口行为,与原生库 diff,产出分析报告(未识别簇+置信度)
3生成特征包符合 db.default.json schema 的增量 JSON,人工在 App 确认后入库(签名+SHA256)
4同步路由器Agent rdpi_feature 命令:备份→合并→reinit→rdpi -e 验证→上报(过渡期走 SSH 通道)
5闭环验证被测设备再跑流量 → flow_dump 出现新 index → 卡片显示「已识别·命中 N 次」,失败自动回滚
