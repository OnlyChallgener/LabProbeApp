# WG / STUN 端口联动与操作反馈

## 范围与基线

- 基于 `codex/ui-material-polish` / `be91c60`，工作分支 `codex/wg-stun-operation-sync`。
- 仅修复 Android WG、STUN、关联收藏的端口归属、增删改反馈及依赖安全。不修改通知、字体、页面布局、隧道数据面或网络协议。
- 本机只执行 Python 检查；Android 编译、Kotlin 单元测试交给 GitHub Actions，不安装本地 SDK、模拟器。

## 实施方案

1. 网关 ListenPort 是当前受管 WG 服务的端口来源。新增客户端不更改服务器端口；自动 DDNS 默认跟随，手动配置保持独立。STUN Endpoint 使用实际公网映射，不等同于服务目标端口。
2. 修改网关时先读取当前修订和完整配置，保留 Peer、端点及未知字段，再提交；等待对应 Agent 应用回执，区分“已提交”“已应用”“穿透待就绪”。仅重定向明确引用该网关的 STUN 规则，不按名字或 51820 猜测。
3. 防火墙由现有 Agent 控制接口负责，不在 App 新增 SSH、绕过接口或清理用户规则。未收到明确回执时不宣称已生效；部分失败保留具体结果，不伪装成回滚成功。
4. WG / STUN 写操作共用应用生命周期的操作状态，点击立即反馈；密钥和存储工作离开主线程。阻止重复和冲突写入，关闭弹层不丢失进度，失败保留可恢复配置。
5. 严格按规则 ID 绑定：不自动换绑；删除 WG 不移除共用穿透或他人的 Endpoint；STUN 删除或改目标先检查引用。
6. 收藏仅同步来源地址及运行状态，保留用户编辑字段；用户取消收藏不在下次轮询重新出现。请求失败不当成空列表处理。

## 验证计划

- Python：源代码约束、测试用例完整性、工作流和修改范围检查；明确这是静态回归检查，不替代 Kotlin 执行。
- GitHub：执行真实 Kotlin 单元测试与 Android 编译，保存测试报告及 APK。
- 必测：自定义 51826；独立手动端口；公网端口不同于目标；共享 STUN 删除；缺失绑定；失败/超时；连续点击；旧快照；收藏保留与取消收藏。
- 真机/路由器验收：保存后即时反馈、页面仍可滚动；网关及防火墙回执；STUN 更新后新映射；实际 WG 握手。未实际执行的不写作 PASS。

## 明确限制与验收边界

- App 只使用已有 Hub / Agent API；没有改动或部署 Agent、防火墙实现。WG 生效取决于对应修订的 Agent 回执；防火墙细分规则仍须路由器实测，不能把单元测试写作真实放行验证。
- 网关和 STUN 分属不同接口，不宣称跨接口原子事务、零断连或已自动回滚。STUN 接口没有现成条件修订参数，App 做依赖校验、提交前重读和冲突提示，但无法保证另一台客户端恰在请求窗口内并发编辑时完全无竞争。
- 操作状态跨页面/弹层保留，非操作系统持久后台任务；强制结束 App 后需从服务器重新核对结果。未确认的创建不得凭等待超时直接视为失败并重复新增。
- 本机不执行 Android 构建、Kotlin 测试或真机网络测试；Python 是静态契约检查。远程编译结果与真实路由器/WG 握手验收分别记录。

## 官方依据

- [WireGuard Quick Start](https://www.wireguard.com/quickstart/)：ListenPort 与 Peer Endpoint 是不同参数。
- [RFC 8489 §2](https://www.rfc-editor.org/rfc/rfc8489.html#section-2)：STUN 返回经 NAT 映射的实际公网传输地址。
- [Android Coroutines Best Practices](https://developer.android.com/kotlin/coroutines/coroutines-best-practices)：耗时工作保证主线程安全，需跨页面完成的工作使用外部生命周期作用域，并暴露可观察状态。
